# 两节点部署执行计划

用户授权在192.168.4.62和.63部署当前系统并删除两机旧部署。复用现有k3s v1.36.4，节点为argus-primary和argus-worker；不连接或清理授权外离线节点192.168.4.61。旧Argus两机工作负载和数据先归档后移除，保留可恢复备份及与离线Edge相关的注册资源。

1. 只读盘点系统、集群、旧工作负载、持久卷、入口与CPU架构。
2. 保存旧Argus配置与数据库/卷备份；准备专用noeriva-system命名空间、Secret、amd64离线镜像。
3. 数据面单实例持久化在62；control/console双副本在两机；worker单实例。通过现有Traefik提供两IP的LAN HTTP入口。真实DNS/TLS可由独立生产值配置。
4. 仅迁移六台真机的资产、加密连接、来源状态、相关发现记录及对应可导出的历史，排除Mock/压测。保持原ID、AAD和vaultkey，新Kafka记录新环境的事件流。源真机采集停用后再启动目标，禁止两个独立数据库同时调度。
5. 配置初始化Jobs、Flyway、允许设备管理网段的NetworkPolicy；确认数据面可达、Ready、镜像架构、存储位置。
6. 在新环境验收六机周期采集、历史、发现关联、浏览器登录与查询，分别通过两IP入口。
7. 清理授权的旧工作负载，检查旧Argus进程在62/63不再运行，记录备份路径和部署实际限制。删除临时明文凭据/Secret工作文件，保留加密部署所需Secret。

这不是数据库或控制平面的高可用认证；62故障将影响单实例数据面。现有集群的离线61节点不因此自动复用或重置。
