# NOERIVA V5 implementation plan

**Goal:** Implement the first executable V5 device operations/query slice and reusable Kubernetes packaging in this initially empty repository.

**Architecture:** MySQL control and source-specific current checkpoints; transactional outbox and durable Kafka event ingestion; bounded WebFlux query module against VictoriaMetrics and ClickHouse; separate synthetic demo profile; Vue device console. No per-sample MySQL writes. Other V5 domains retain their full roadmap requirements.

**Tech stack:** Java 25, Spring Boot 4.1.1, WebFlux, R2DBC, Vue 3/TypeScript/Vite, Redis, Kafka, VictoriaMetrics, ClickHouse, Helm.

**Spec:** `docs/source-v5/NOERIVA_MASTER_PROMPT_V5.md`; latest user instruction authorizes implementation and deployable K8s artifacts. Existing confirmed B/Clarity decisions apply. The historical architecture-review mode is superseded for this local implementation. Production deployment and real-device operations are outside this run.

- [x] Control: authenticated organization-scoped API, inventory/current state, independent source freshness, optimistic alert transitions, transactional outbox, durable ingestion and idempotent projections. Test security, replay/future data, pagination and transactions.
- [x] Query: exact counter arithmetic, reset/gap-aware versioned rollups, timezone/DST-aware 168-cell heatmap, bounded metrics and concurrency admission. Test correctness before enabling UI.
- [x] Console: implement B/Clarity device list, overview, detail/trends/heatmap, connections, events/alerts/collectors, explicit source and error states. Typecheck/build/component tests and rendered browser inspection.
- [x] Deployment: Compose local dependencies, Helm application workloads against managed stores, compact Kubernetes reference, probes/resources/HPA/PDB/security/network controls and operations docs. Render/lint/validate and local container integration.
- [x] Verification: run combined unit/integration checks, real backend/UI smoke, synthetic concurrency benchmark with hardware and limitations, independent code review, capability evidence and handoff.

**Global constraints:** scope derives from authenticated principal, never client-supplied organization headers; no secrets in Git/browser persistence; current state never scans raw history; query errors never become zero/NO_MATCH; numerical metrics bypass Kafka; query admission is bounded and cancellation-safe; source times are not refresh times; demo is visibly identified; no unverified throughput, vendor, WORM or HA claims.

**Verification evidence:** docs/implementation/VERIFICATION.md records 66 backend tests, frontend checks, actual COMPACT state and metric-repair pipelines, measured local concurrency baseline and deployment validation. Completed items above are the explicitly scoped first slice, not the Phase 0–13 product roadmap. Production Kubernetes rollout and HA acceptance remain unperformed.
