# 澄明工作台：逐页功能与目的

日期：2026-09-09。设计依据：用户指定 `/Users/hades/Downloads/preview.html` 的 B / Clarity / 澄明工作台。本文将每页目的、当前实现和验收条件对应起来；实际执行过的验证及限制见[验收报告](CLARITY-VERIFICATION.md)，不能用设计目标代替验收结果。

## 产品结构与共同约定

面向值守人员、网络/主机管理员和审计人员：先巡检发现异常，再进入设备及事件上下文，最后用有来源的记录验证判断。导航按工作空间、基础设施、运行响应、审计与治理、平台分组。原 14 个主导航页面增加独立应用监测、NAT 审计，共 16 个主导航页面，加资产上下文中的设备详情共 17 个主业务页面；资产下 `/assets/discovery` 为候选审核辅助页，不增加一级导航；`/system` 是系统设置页可进入的附加能力说明页，不另计业务页。原型中的“四种方案评审栏”“预览页面状态”“选择与反馈”属于设计工具，不进入业务页面。

采用参考稿的浅色方案：背景 `#f3f6fa`，面板 `#fff`，侧栏 `#f9fbfe`，主文字 `#172538`，次文字 `#526478`，分隔线 `#d6dfe9`，强调色 `#255ea8`；侧栏 256 px，页内边距 28 px，主字号 14 px，标准行高 44 px，紧凑 36 px。总览采用开放主列与右侧轨道，不以统计卡片网格替代优先巡检表格。手机导航收进抽屉，表格在自身区域横向滚动。

所有业务记录通过登录身份确定组织；目前权限边界是组织和角色，站点筛选不等于细粒度站点授权。VIEWER 可查询和发起只读关联调查；OPERATOR/ADMIN 可登记及编辑资产基础资料、运行已存邻居证据发现及审核候选、确认告警、维护事件和探测定义；设备连接设置、凭据写入、测试、立即采集与周期启停仅 ADMIN；所有读角色可查看不含连接用户名和秘密的采集结果；证据/配置导入仅 ADMIN；探测结果及网络证据由 COLLECTOR/ADMIN 上报。前端隐藏按钮不能代替后端授权。

缺失值显示“—”，从未采集、过期、离线、错误分别呈现。查询有加载、空结果、权限错误、上游错误和重试状态。资产、事件及新的目录/工作流列表使用有界游标分页；告警、采集器、站点及拓扑是各自有上限的结果集，不能据当前页数量推断全量。仅在当前结果进行的过滤注明范围。业务时间以 UTC 保存，以用户选定时区展示；调查和手动导入时间输入明确 UTC，原始 JSON 保留原始时间表示。

顶栏统一搜索提供页面、资产、端口和事件结果，显示后端实际搜索引擎与索引状态。端口结果携带 `deviceId` 与 `interfaceId` 进入设备接口页，高亮对应行；结果是否完整由服务端索引状态决定。页面关键字只用于导航，不能据此认定协议能力已接入。界面不保存密码，导出不伪造签名、设备兼容性或法律效力。

## 1. 运行总览 `/overview`

**目的**：在一分钟内回答“哪里需要先看、发生了什么、数据是否新鲜”。

**布局与字段**：主列三个开放统计区（资产总数与健康分布、活动告警、状态统计时刻），最多 10 台优先巡检设备、单设备 RX/TX 趋势和站点健康表；右列全工作区待确认告警及最近变化。活动告警指尚未 RESOLVED，包含已确认记录；右列仅取 OPEN，两个数字不必相等。`stale` 仅计最近观测非空且距统计时刻超过 180 秒的资产，从未观测的 MISSING 资产不算过期。

**操作与范围**：切换站点、刷新、打开目录/设备/告警/事件。站点作用于汇总、优先巡检、站点健康及带宽来源选择；右侧告警仍是全工作区最多 5 条。选站点后最近事件停止查询并提示按设备进入事件页；未选站点时取最近 7 天最多 5 条。带宽来源从当前范围选取最新含带宽指标的一条，显示设备与 sourceId；当前值来自该来源，历史按设备与指标查询，不是全站流量聚合。

**支撑与验收**：`GET /workspace/overview`、`GET /alerts?state=OPEN&limit=5` 及设备 metrics API。用相同范围、接近的统计时刻核对资产/告警状态；验证一台从未观测、一台已观测过期只计一台过期。无带宽来源是等待采集，历史不可用要显示错误/质量状态，不能替换为零事件或零流量。

## 2. 资产目录 `/assets`（兼容 `/devices`）

**目的**：按稳定身份管理资产，并从登记进入可追踪的协议接入流程。

**字段**：主表显示名称/管理地址、类型、健康、可用性、站点、厂商/型号和最后观测。UUID 是链接和导出的稳定标识；管理 IP 不作为主键。登记品牌型号与协议实际识别结果分开展示，发现结果不会自动覆盖管理员资料。

**操作**：名称/IP 字面前缀搜索，站点/类型/健康筛选，清空筛选，游标翻页，导出当前页 CSV。ADMIN/OPERATOR 登记名称、类型、站点及管理地址，厂商/型号可选；默认勾选“保存后继续接入配置”，成功进入 `/assets/:id?tab=access`。取消勾选可仅登记库存。创建本身不访问目标，初始状态未知。

**接入顺序**：登记 → ADMIN 配置 SNMP、Redfish 或固定档案 SSH 连接 → 保存 → 测试识别 → 检查实际能力与质量标记 → 立即采集 → 启用周期采集。OPERATOR 可先建档及编辑资料，由 ADMIN 完成凭据步骤；VIEWER 仅查看。

**支撑与验收**：`GET/POST /devices`、`GET /sites`，后续操作使用设备接入 API。核对组合筛选与翻页无重复、创建后重读及跳转、组织隔离、只读账号拒绝写入；CSV 只导出当前页，保留 UUID，并处理公式前缀及引号。大库存不全量下载到浏览器。表单级细节见[设备接入说明](../devices/DEVICE-ONBOARDING-UX.md)。

## 资产辅助页：发现设备 `/assets/discovery`

**目的**：从明确授权范围内的已存邻居事实整理待管理对象，人工解决重复疑点，然后登记新资产或关联已有资产。

**输入与运行**：必须明确填写规范 IPv4 CIDR `/24`–`/32`，选择站点和 1–8 个同站点来源设备。来源选择器使用有界名称/IP 前缀查询；站点变化清空旧选择。ADMIN 可从来源链接进入接入页手动采集，发现页本身不自动采集、不扫描、不读取凭据。OPERATOR 可直接整理已有安全事实。`POST /discovery/runs` 只读少于 15 分钟且不在未来的保存结果，每来源最多 256 条；分别报告 USED/MISSING/STALE/INVALID、观察数、候选统计和质量标记。

**审核与状态**：`GET /discovery/candidates` 按站点、状态、不透明游标分页；展示 IP、名称、MAC、NEW/EXISTING/LINKED/REGISTERED/POSSIBLE_DUPLICATE/CONFLICT、原因及来源观测时间。详情最多 16 条 ARP/LLDP/CDP 证据，包括来源设备、接口/VLAN、chassis subtype/port、ageMinutes、TTL 和 validUntil。候选 lastSeenAt 不是在线证明；读取不到来源不等于没有设备。

**登记/关联**：NEW 可填写名称、类型并登记，POSSIBLE_DUPLICATE 先明确勾选已核实独立资产，CONFLICT 只允许人工关联同站点既有资产。register/link 均提交当前 revision；409 后重读供审核，不自动重试写入。成功后进入实际资产，登记默认继续接入。已关联候选保持稳定关联；不复制来源密钥、不更改既有资产管理地址、不物理合并历史。共享 MAC、名称或 SSH key 都不足以自动确认同一设备。

**支撑与验收**：四个发现 API 及有界设备/站点目录，写角色 ADMIN/OPERATOR、读角色含 VIEWER。验证明确 CIDR、同站点选择、无 collect 副作用、陈旧/缺失来源提示、重复确认、冲突关联、409 无盲重试、纯文本证据与分页。服务端每实例并发 4、关联窗口 1024 行、事务总预算 10 秒，超限分别 429/503。完整契约与去重边界见[发现 API](../devices/NETWORK-DISCOVERY-API.md)；真实硬件格式见[型号记录](../devices/HARDWARE-FORMAT-NOTES.md)，实际 26 个候选与 1 个已有资产关联见[六台真机验收](../devices/HARDWARE-VERIFICATION.md)。

## 3. 设备详情 `/assets/:id`（兼容 `/devices/:id`）

**目的**：在同一设备上下文完成资料维护、协议接入、读取确认与持续巡检，串联历史和后续处置。

**信息区**：身份、管理地址、站点、状态与最近观测。八个页签为概览、传感器与监测、接口与带宽、资产关系、事件与告警、配置与变更、原始资料、接入与采集。事件、配置和证据工作流携带 deviceId 跳转；“配置与变更”审阅快照，“接入与采集”管理协议连接，二者用途不同。

**接入与采集**：资产资料卡用独立 `inventoryRevision` 编辑名称、类型、站点、厂商、型号和管理地址，遥测更新不会制造资产编辑冲突；409 后明确重读。SNMP、Redfish 和 SSH 各一张独立连接卡、独立 revision，来源分别固定 network / bmc / ssh。管理地址仅提供首次目标初值，后续编辑资料不转移已有凭据。

**凭据与操作**：只有 ADMIN 可配置、测试、立即采集、启停。SNMPv2c community、v3 用户/安全级别/context 与认证加密算法按实际设备设置输入；默认 SHA256/AES128，SHA512 可选，SHA1/MD5/DES 需显式选择旧固件兼容，不自动降级，不支持 AES256。新 auth/priv 密码至少 8 字符。Redfish 提供 SYSTEM 信任或 PINNED SHA-256，不提供跳过证书验证。SSH 提供 iMana、Dell OS9、Cisco IOS XE 三种固定只读档案，独立用户名/密码和必填 OpenSSH SHA256 主机密钥指纹，先校验 key 再认证；没有任意命令输入或自动降级。已有秘密只显示存在标识；同目标同有效身份留空保留，host/port/context/TLS pin/SSH profile/SSH host-key pin 等有效身份变化要求重新输入对应秘密。未配置凭据存储时有明确空态。界面保存连接时关闭周期采集，提示测试后启用；测试与立即采集均使用已保存版本。

**实时结果**：分别呈现周期启用状态、NOT_TESTED/QUEUED/RUNNING/SUCCESS/PARTIAL/ERROR/DISABLED、最近尝试/成功/下次计划、错误码、结果观测时间、实际身份/profile、传感器、端口、能力及质量标记。HTTP 200 仍需读取结果状态；失败保留上次成功资料及其原时间。所有读角色通过安全 collection 与带 Authorization 请求头的 SSE 查看结果；SSE 断开时查询兜底，切换设备/离开页清理旧连接。读取成功不等于所有指标可用，也不自动证明硬件兼容。已有 SSH 来源仅提供身份/邻居、无数值能力时，趋势显示“暂无数值指标”，说明网络流量需 SNMP 等接口计数来源；只有 summary.sources 为空时使用“等待监测来源”。

**独立网络工作流**：路由器、交换机和防火墙的页首提供携带 deviceId 的应用监测与 NAT 审计入口；接入页通过安全 sources 投影显示各自的启用状态、版本、成功/接收时间和质量。应用采集复用 SNMP 凭据，但其周期独立于基础 SNMP enabled；NAT 为独立被动接收。两模块的 ADMIN 配置与启停位于对应独立页面，不混入设备连接秘密表单。应用 sources 一次最多读取 200 条；若当前设备不在本页且仍有后页，明确不能据此判定未配置。

**历史与接口操作**：相对时间窗在进入可见概览/监测、切换设备/指标/小时数时推进到当前时间，并在可见页每 20 秒推进；隐藏/离开时清理计时，确保新采集样本进入查询窗口。选择指标/时间窗、展开数值、查看独立来源及 epoch/sequence、切换接口和 RX/TX、点击热图小时查看覆盖区间、选择关系节点。七日热图默认查询设备汇总（`/devices/{id}/bandwidth/heatmap`），以小时采样均值展示已采集接口进出口之和；逻辑/物理接口可能重叠，不是去重全网流量。可选择具体接口，单接口保持时间加权均值。“查看带宽”保留 interfaceId 并切换监测，接口按自然字母数字顺序排列。传感器与监测页额外列出所有已返回组件读数，支持筛选名称/指标/来源；过期读数不显示为当前健康。单位按数值显示 bps/Kbps/Mbps/Gbps、W/kW。SNMP 立即/周期采集会写入成功观测的接口元数据；接口手动登记已有 API，详情没有额外登记表单。

**支撑与验收**：summary/interfaces、`/topology?deviceId=...`、metrics、bandwidth/heatmap、events，以及 management/updates、connections/actions、collection/live 和 device-support API。验证资料与连接版本独立、角色和组织隔离、秘密不回显/不进入浏览器持久存储、真实请求字段、算法动态校验、SSE 清理和错误兜底。协议模拟器验证与真实型号验收分开记录；缺口、覆盖率、未定稿和夏令时按查询响应展示，缺失传感器及接口容量不能补零或替代流量。完整契约见[设备 API](../devices/DEVICE-INTEGRATION-API.md)与[九族支持对照](../devices/DEVICE-SUPPORT.md)。

## 4. 基础设施拓扑 `/topology`（兼容 `/connections`）

**目的**：观察已有物理与管理关系，核实关系依据，为影响分析提供上下文。

**字段与操作**：有界节点/边子图、设备类型/健康、接口端点、关系类型、来源和观测时间；限定设备邻域、节点选择、拖拽/缩放/适应视图、布局控制、可访问节点列表、检查器及设备跳转。路由器使用圆形，交换机使用五边形，带外管理使用三角形，服务器使用方形，防火墙使用菱形；显示形状图例、健康边框以及连线的端口标签。当前没有独立协议层筛选或历史拓扑回放。邻域下拉来自首 100 台资产，不是完整资产搜索器。

**支撑与验收**：`GET /topology?deviceId=&limit=200`，最多 200 节点/400 边；设备详情复用 `/topology?deviceId=...`；`/devices/{id}/connections` 已专用于 ADMIN 连接设置。确认节点/列表选择一致且可用键盘进入详情。连线完全来自服务端匹配后的观测，零关系时明确提示检查邻居采集与身份匹配，不补猜测连线。实际设备邻居匹配与连线结果以本轮硬件验收为准。

## 5. 监测与传感器 `/monitoring`

**目的**：在全组织范围确认采集发布后的指标来源，定位缺失或过期数据，区分独立来源当前值和设备级历史趋势。

**字段**：设备/站点、sourceId、最近投影事件 kind、健康、新鲜度、观测时间、指标值。kind 是 `DeviceSummaryObserved` 等事件种类，不能解释成已验证的 SNMP/Redfish/SSH 协议。列表每行展示前 4 个当前指标；选中后可从已提供的支持指标中选择温度、功率、CPU、内存或带宽。

**接入关系**：成功测试只保存安全读取结果，不发布到时序/事件链路；立即或周期采集通过既有链路发布，SNMP 使用 network、Redfish 使用 bmc、SSH 使用 ssh。同一设备的同名历史指标由服务端绑定一份 slot，Reading 的 `publishedMetricIds` 说明本次实际发布范围，不能假定多个协议的相同指标都进入同一条历史曲线。SNMP 带宽摘要是本次返回接口的速率和，逻辑/物理接口可能重叠；Redfish 温度摘要是成功读取温度的最大值，整机功率只在唯一明确完整总量成立时发布，不能视为平均温度或各 PSU 功率相加。iMana SSH 的设备温度也是已采集可用温度最大值；风扇、电压、电流等详细传感器在接入结果保留真实单位，未获历史发布能力时不能伪造趋势，离散位未解码时显示状态项。

**操作**：设备名称/IP/sourceId 前缀、站点、新鲜度过滤和游标翻页；关键字 Enter 提交、失焦提交，逐键输入不查询；deviceId 可从设备上下文传入。选择指标、15 分钟/1 小时/6 小时趋势、数值表及设备跳转。列表批量查询 MySQL 当前投影，只有选中指标才访问时序库。

**支撑与验收**：`GET /workspace/monitoring` 和 `GET /devices/{id}/metrics`。历史接口没有 sourceId 参数，页面分别标出当前来源与历史服务来源，不宣称趋势严格归于所选 sourceId。验证无 N+1 请求、指标单位、覆盖率、过期来源最后值及缺失不补零；没有来源的资产不产生伪传感器行。

## 6. 网络接口 `/network`

**目的**：检查 SNMP 已发现或人工登记的接口，定位端口、实际状态与可用带宽历史。

**字段**：接口/设备、站点、MAC、标称速率、管理状态、运行状态、最近设备观测及设备新鲜度。`deviceLastSeen` 不是接口独立观测时刻；null 或零容量按未知显示，不能从空值生成零流量。SNMP IF-MIB 按实际行读取名称/MAC、管理/运行状态和计数器，Counter64 原值以十进制字符串保留；稳定接口标识不单凭可变 ifIndex。

**操作**：接口/设备名称或管理 IP 前缀搜索、站点筛选、重置、游标翻页、打开设备接口/监测和拓扑；deviceId 可从上下文限定。VLAN、LACP/STP、BGP、光模块字段与协议采集尚未进入该目录 API，属于后续适配内容。新 SSH ARP/LLDP/CDP 结果在发现候选详情展示来源、年龄、TTL 和 chassis/port 证据；这些信息不等于 IF-MIB 接口目录或已确认拓扑。

**接入关系**：测试结果的端口先在接入页查看，立即/周期采集再写入目录。完整、无质量问题的接口快照可将本来源消失端口标为 NOT_PRESENT；部分读取保留历史接口，不能用截断列表宣布端口消失。带宽需要至少两个连续、可比较计数样本；基线、重启、断代、缺口、宽度不充分或容量不明时按实际质量状态呈现。

**支撑与验收**：`GET /workspace/interfaces` 批量 SQL；速率在 API 中保留十进制字符串，展示格式化为容量单位。热图及修复任务按已授权接口目录的 source_id 选择来源，人工登记通常为 primary、SNMP 为 network，调用者不能指定另一来源。验证过滤、游标及接口设备归属，区分未知/离线/过期；核对带宽入口进入真实指标及接口热图，而非把容量画成流量。

## 6a. 应用监测 `/applications`

**目的**：独立配置 Cisco NBAR 接口/应用汇总读取，并区分原始计数、设备报告速率和平台相邻样本差分。它不提供客户端 IP、五元组、会话数、完整 URL 或 NAT 映射，不把名称分类解释成用户行为。

**来源与配置**：来源目录只列已有同组织 SNMP 槽的设备，按不透明游标分页。展示应用独立 revision/enabled/status、SNMP credentialRevision、明确选择的 ifIndex、周期、协议行上限、最近尝试/成功/下次计划、实际方向观测行数、错误码与质量。SNMP 连接存在不代表 NBAR 已支持或开启。ADMIN 保存 1–8 个互异正整数 ifIndex、30–3600 秒周期及 1–256 协议行总限额；服务端要求 `maxRows >= 选定接口数`，否则返回 400；不把平台接口 UUID 或前 N 个接口当选择。设置、启停、立即采集均提交应用版本；409 重读并要求检查后重试，不自动重放写操作。周期停用时仍可手动采集；平台开关不修改路由器协议发现配置，也不更改基础 SNMP 开关或要求再次输入秘密。所有读角色只访问安全投影和历史。

**默认概览**：进入应用页自动选择已启用来源，通过 `/applications/summary` 加载最近真实采样的应用带宽柱状图，最多 12 个应用方向。平台差分为柱值，设备报告速率在可访问表格单独展示；初次基线缺失保留为空。来源、观测时间、新鲜度、样本数、截断和跨接口重复可能性都可见。

**历史与质量**：选择设备、可选 ifIndex/IN–OUT/应用名称包含匹配，明确填写 UTC 固定时间范围，最长 7 天。提交后每页 30 个方向观测行；输入改变清空旧结果和游标，不逐键查询，分页使用与全部筛选绑定的游标。时间窗保持提交时定义；“设为最近 1 小时”明确更新输入后再查询，立即采集后提示重新设定时间以覆盖新观测。来源状态每 20 秒刷新，历史只显式查询/重试，离开页面取消请求。

原始 bytes/packets 以十进制字符串展示，保留 Counter64 精度；reportedBps 标为设备报告速率，derivedBps/derivedPacketsPerSecond 标为平台差分，并展示实际样本间隔。未知数值为 —，观测为 0 才显示零；首次、重启、凭据或接口身份变化、计数下降、过长间隔等质量标记不能被图表补零。协议行余量按剩余已启用协议发现的选定接口公平分配，早接口未用额度可供后续接口使用，总上限仍为 256；各接口按 OID 前缀有界读取并截断，`NBAR_ROW_LIMIT` 必须可见。覆盖仅指选定接口与本轮保留协议行，不承诺全协议覆盖或跨轮次轮转；API 未提供覆盖比例或采样率，页面不推算百分比/全网总量。来源记录弹窗保留原始字段、epoch 与质量；不将当前页累计计数相加生成流量排名。

**支撑与验收**：五个独立 [应用 API](../devices/APPLICATION-MONITORING-API.md)。组件回归验证只读权限、独立版本/凭据复用、大计数保真、缺失与零区分、显式接口校验、停用周期仍可手动读取、筛选和游标绑定。协议模拟器、真实设备 NBAR 对象权限、历史持久化与部署后 Computer Use 验收另行记录，前端 fixture 不代表真机或链路已经可用。

## 7. 告警队列 `/alerts`

**目的**：识别异常并明确是否已有人关注。

**字段与操作**：严重度、标题、设备、开始时间、OPEN/ACKNOWLEDGED/RESOLVED；状态与设备上下文由服务端过滤，等级仅过滤当前最多 50 条。刷新、确认、查看确认人/时间/revision，从告警打开创建事件表单并预填设备和告警 ID。已有事件单不支持事后改绑告警。

**支撑与验收**：`GET /alerts`、`POST /alerts/{id}/acknowledge`、incident 创建 API。确认带 revision，冲突重读；VIEWER 无写权限；确认审计保留操作者。确认只变成 ACKNOWLEDGED，恢复由后端状态机处理，当前队列没有人工恢复按钮或完整游标浏览。数字指标阈值规则编辑、通知与值班升级尚未实现。

## 8. 事件工作台 `/incidents`、`/incidents/:id`

**目的**：将告警和现场记录组织为可交接、可复查的处置过程。

**布局与字段**：列表展示编号、标题、严重度、状态、负责人和更新时间；详情展示创建与备注时间线、关联设备/告警、版本及处置表单。列表仅返回 `IncidentSummary` 元数据和 noteCount，备注正文按详情读取，最多 100 条。

**操作**：状态筛选、设备上下文筛选、分页、创建独立或关联告警的事件；编辑标题、组织内负责人账号，追加备注，切换调查/解决/重新打开。UI 保存处置要求填写说明；API 对解决状态强制非空说明，其他更新允许仅改元数据。负责人必须是同组织有效账号，不是自由人员身份字段。设备、严重度和关联告警在创建后不能改绑。

**支撑与验收**：`GET/POST /workbench/incidents`、`GET /workbench/incidents/{id}`、`POST /workbench/incidents/{id}/updates`。验证持久化、同事务审计、错误设备/告警关系拒绝、旧 revision 返回 409、跨组织不可见、切换详情不带入另一事件的版本。假设使用备注记录，不自动升级为事实或结构化证据关联。

## 9. 事件流 `/events`

**目的**：检索已收到的基础设施事件，不与人工事件单混淆。

**字段与操作**：主表展示观测时间、类别、设备、内容、等级和来源；JSON 检查器保留接收时间、质量标记及原始字段。服务端按设备、时间与游标查询，每页 25 条；页面提供最近 1 小时/24 小时/7 天/30 天。文本和类别只过滤当前页，明确显示命中数与当前页总数。

**支撑与验收**：ClickHouse `GET /events`，API 最长 31 天。刷新重置查询终点与游标；支持设备上下文及来源弹窗。验收源时间保留、重放去重、分页和过滤范围；空结果不能排除采集缺口，上游故障不能显示成“没有事件”。

## 10. 关联调查 `/investigator`

**目的**：回答一个带时间的端点在已保留证据中对应哪些地址和设备，同时展示无法确定的部分。

**表单与结果**：公网→私网/私网→公网、字面 IPv4/IPv6、端口、TCP/UDP、UTC 时刻。结果保留提交时定义；展示 CONFIRMED、AMBIGUOUS、INSUFFICIENT_EVIDENCE 或 NO_MATCH，NAT 候选、租约、有效区间、时钟误差、来源与质量标记；可查看原始记录、打开租约设备、下载本次查询 JSON。

**关联规则**：NAT 的 deviceId 是观察网关，ADDRESS_LEASE 的 deviceId 是租约主体，可为不同设备。服务端导入时从设备记录固化 siteId，以同组织、同固化站点、同私网 IP、同 provenance 和时间区间关联。跨站点租约不能补足归属；同站点多条有效租约仍是歧义。固化站点不是独立验证的历史位置或 VRF，也不确认现实人员身份。

**支撑与验收**：`POST /workbench/investigations`；typed network-evidence 由 COLLECTOR/ADMIN API 导入，当前无浏览器导入表单。有效区间为 `[validFrom, validTo)`；最多 100 个 NAT 候选和 100 条租约，超限 429，不截断后生成确定结论。验证四种结果、同站点不同设备可确认、跨站点隔离、时钟误差及端点边界。NO_MATCH 只表示未找到已保留匹配 NAT；普通事件字符串不能代替 typed 证据。查询 ID 关联审计，下载 JSON 不等于持久、签名的取证包。

## 10a. NAT 审计 `/nat-audit`

**目的**：独立观察 Cisco NAT HSL NetFlow v9 的接收质量并检索保留事件，和基于完整 typed 区间/租约的关联调查分开。CREATE、DELETE、POOL_EXHAUSTED 分别显示创建观测、删除观测、地址池耗尽；单个创建/删除观测不等于完整会话，不制造存续区间、NAT 使用者身份或 NBAR 分类。

**接收来源**：最多 256 个已配置源，显示登记网关、真实导出 IPv4、独立 revision/enabled、WAITING/RECEIVING/DEGRADED/STALE/DISABLED、最近报文、最近接纳事件的接收时刻、持久化确认时刻及安全错误。ADMIN 绑定来源，地址留空提交 null 使用当前设备管理 IPv4；不支持 DNS/CIDR，也不要求设备口令。settings/state 提交当前版本，409 后重新读取；启停最长约 5 秒生效，已接纳事件可继续持久化，历史保留。平台接收设置不会修改路由器导出配置，也不切换 SSH 或 SNMP 采集。

**计数边界**：模板定义/刷新、收到报文、Kafka 接纳、持久化确认、拒绝报文、序列缺口、未知模板、解析错误、重复报文和重启分开显示。计数自来源配置创建累计；持久化运行计数可能因重试重复，不能作唯一事件数量。序列跳号不等于确定丢失多少事件，零拒绝也不是无丢失证明；UDP 未经密码学认证、不保证完整性，接收器重启可能损失未刷新计数。页面不把 RECEIVING 展示为已完整审计。

**历史查询**：进入后自动选择已启用网关，默认省略 from/to 查询全部保留历史，按平台接收时间从新到旧。可切换自定义 UTC 时间范围，不再限制为 24 小时；可选 0–255 整数协议号、私网/公网 IPv4 精确匹配。每页最多 30 条，游标冻结首次截止时间，条件变化清空旧结果和绑定游标。去重后本页可能为空但仍有 nextCursor，页面保留下一页按钮并说明继续读取更早记录。表格分开呈现 receivedAt、可空 deviceEventAt，以及协议/VRF、内外端点、目标/转换后目标与质量；来源详情包括 exportedAt、sourceDomain、exporterEpoch、模板/报文摘要和记录位置，不提供原始 UDP 载荷。端口字面 0 保留，缺失为 —；非 TCP/UDP 不解释成相应传输层端口。空结果只表示当前范围无保留记录，503 显示错误，不替换成零事件。

**支撑与验收**：四个 [NAT 审计 API](../devices/NAT-AUDIT-API.md)。组件回归覆盖角色与安全字段、版本冲突和重复打开配置保留版本、空来源地址按 null 提交、时间上限、筛选绑定游标、零端口和未知设备时钟。关联调查页提供审计入口并明确两套证据用途；当前不把 HSL 单事件自动写入调查的 COMPLETE 区间或地址租约。真实 exporter、UDP 来源保留、模板解码、Kafka/ClickHouse 与硬件验收以服务端和部署报告为准。

## 11. 证据资料 `/evidence`

**目的**：保存可复查的来源记录及完整性校验信息。

**字段与操作**：ID、标题、类型、设备、source/provenance、观测/保存时间、SHA-256、签名状态。按标题前缀和设备上下文查询、翻页、查看纯文本正文及读取审计、ADMIN 手动登记、导出服务端 manifest 与内容。列表不传输正文；详情按需读取。

**支撑与验收**：`GET/POST /workbench/evidence`、detail/manifest 及 audit。正文最多 32768 字符且 UTF-8 不超过 64 KiB；不可覆盖/删除。读取及导出重新校验正文 UTF-8 字节的 SHA-256，损坏返回 409 并审计；下载后可独立复算。`UNSIGNED`、`worm:false` 必须保留，不宣称签名、对象锁或法律保全已部署。证据类型标签 NAT/LEASE 不会自动生成调查使用的 typed network-evidence。

## 12. 配置与变更 `/configuration`

**目的**：比较只读快照，识别具体变化并保留来源。

**字段与操作**：设备、快照标题/时间、source/provenance、摘要及脱敏行数；ADMIN 选择设备后可立即同步实际只读配置，读取最近同步状态和失败原因；自动同步开关/周期位于系统设置。也可导入已脱敏文本，列表查看脱敏原文与下载，选择同设备前/后版本，查看逐行新增/移除/未变及下载差异 JSON。当前选择器使用已加载列表，不代表已下载该设备全部历史。

**支撑与验收**：`/workbench/configuration/snapshots` 的 list/create/detail、`GET /workbench/configuration/diff` 及 `GET/POST /workbench/configuration/devices/{id}/capture`。每份文本最多 65536 个 Java 字符单元、UTF-8 128 KiB、2000 行。服务端存储前过滤已支持的凭据行、URL 凭据与私钥块；这只是模式脱敏，导入前仍须确认原文已脱敏，不能保证识别所有厂商格式。验收已覆盖模式不落库/不回传明文、同快照零差异、跨设备比较拒绝、内容损坏 409 审计。没有配置下发、重启、自动恢复或变更审批执行器。

## 13. 采集器 `/collectors`

**目的**：观察协议采集 Worker 是否持续工作，再到设备接入页检查具体目标的配置、成功时间和错误。

**字段与操作**：模型包括身份/站点、版本、能力、最后心跳、最后成功采集、队列大小/容量、最早积压时间和 source。页面支持刷新、原始状态和监测来源入口；心跳正常不证明设备在线。设备级测试、立即采集和周期启停位于 `/assets/:id?tab=access`，不在本页重复提供控制按钮。

**当前接入**：`GET /collectors` 已可读取由内置设备协议 Worker 写入的 device-poller 心跳，能力按当前驱动注明 SNMP/REDFISH/SSH 和只读/租约相关标志。Worker 记录与安全 collection 结果各有时间，需同时核对；它不是每台设备一条采集器记录，也不是每个副本的独立进程目录。API 节点不执行周期调度，`collectorEnabled` 只是部署能力提示，不能当实时心跳或禁用手动测试的依据。

**当前边界**：没有外部 Edge 注册、通用心跳写入 API、双向 TLS 任务下发或本地持久断网队列。内置 Worker 的 0/0 队列字段表示没有这类缓冲容量，不能据此认定已完成缓冲链路验收。`POST /ingest/batches` 本身不写采集器心跳。没有启动 Worker 的空目录与上游服务错误分别呈现，DEMO 的 SIMULATED 记录不算真实接入。

**支撑与验收**：检查 Worker 心跳持续更新、暂停或故障后时间停止、设备成功时间独立、启用设备是否产生后续观测；模拟器端到端结果以设备验收报告为准，不预先声称实机完成。队列容量为零不除零，空时间不等于不存在积压。完整 Edge 能力仍需注册、身份、缓冲状态及断连/恢复测试；不提供远程重启。

## 14. 合成探测 `/checks`

**目的**：管理 TCP/HTTP/HTTPS/DNS/TLS 检查定义，执行真实只读网络探测并查看历史结果。

**字段**：名称、关联 deviceId、目标、类型、间隔、启用/归档状态、revision、最近结果和来源；历史按新到旧展示最多 30 条及结果格，包含 definitionRevision。没有独立 siteId 探测授权字段，关联设备仅提供上下文。无结果为 UNKNOWN，缺少延迟显示“—”。

**操作**：名称前缀/设备上下文查询、定义分页、创建/编辑、启用/停用、查看最近历史与关联设备。归档按钮需在对话框确认，归档保留历史并拒收新结果。结果历史使用不透明游标，可继续翻页查看更早记录。没有删除定义或浏览器执行目标的操作。

**支撑与验收**：`/workbench/checks`、detail/updates/archive/results 和 `POST /workbench/check-results`。每次定义更新递增 revision 并清空最近结果投影，旧历史保留版本；旧版本上报 409，同 ID 同内容幂等、冲突内容拒绝。检查类型/设备/provenance 创建后固定，归档后拒绝新结果。MANUAL 定义由内置 worker 遵循 enabled 和 interval 调度，OPERATOR/ADMIN 可提交当前 revision 立即执行；手动执行不改变周期。归档仍拒收结果，修改期间完成的旧版本探测被拒绝，不覆盖当前版本。

**执行与限制**：`POST /workbench/checks/{id}/run` 使用组织内保存定义，内置 worker 每 5 秒有界扫描，每实例最多 4 个网络探测；MySQL 租约避免同一检查跨实例重复并行。目标先经 TargetPolicy 解析并验证全部地址在允许网段，再连接固定已验证地址；HTTP 不跟随重定向或使用凭据，TLS 使用系统信任和目标身份验证。DNS 表示系统解析器成功解析到允许地址，非指定服务器的 DNS 权威性验证。策略拒绝/输入无效记录 UNKNOWN，网络/TLS/超时失败记录 FAIL。SYNTHETIC 定义仅保留外部测试上报，内置执行器不会把合成fixture作为真实网络任务。

## 15. 系统设置 `/settings`

**目的**：集中管理组织运行参数、读取搜索/数据状态，以及个人偏好和账号安全。

**组织设置**：ADMIN 编辑工作区名称、组织默认时区、新建连接采集周期/超时/接口上限、只读配置自动同步开关和周期。带 revision 保存，409 保留未保存输入并提示重读；放弃未保存修改可恢复服务端最新值。新连接使用组织默认值，用户开始输入后不覆盖；既有连接不改变。VIEWER/OPERATOR 读取设置但不能修改组织策略。

**搜索与数据**：显示实际搜索 provider/status、最近索引时间、历史保留状态与只读配置捕获语义。ADMIN 可触发真实索引更新，设置页可进入配置同步和系统能力。组织与运行参数通过 `GET/POST /settings` 持久化，索引更新用 `POST /search/reindex`。

**个人偏好与安全**：浅/深主题、标准/紧凑密度、个人时区、减少动画、重置偏好；显示当前账号/组织/角色。`POST /settings/password` 提交当前密码与新密码，确认密码仅本地校验；请求后清空三个密码字段，不写浏览器持久存储。个人偏好保存在浏览器，优先于组织默认显示习惯；系统的减少动态效果设置始终受到尊重。侧栏可用滚轮、触摸和键盘滚动，隐藏视觉滚动条；窄屏抽屉保留完整导航。

**支撑与验收**：新增组件测试覆盖设置 revision 保存、VIEWER 只读、新建连接默认值与既有连接保留；端口搜索测试覆盖对应设备/接口跳转。系统能力矩阵与 `/device-support` 仍分别表示平台能力、驱动匹配目录，不能把实现标志提升成品牌全系实机支持。真实持久化、索引和密码流程以本轮服务端与部署验收为准。

## 数据、性能和上线依赖

- MySQL 控制面、VictoriaMetrics 时序、ClickHouse 历史聚合、Kafka 异步摄入、Redis 会话职责分开。目录不逐台调用上游；工作台列表页最多 100 项，正文与备注不进入元数据列表；查询、调查候选和差异输入都有上限，详见[聚合查询契约](../implementation/WORKSPACE-API.md)和[工作流契约](../implementation/WORKBENCH-API.md)。
- 新业务写入包括角色、组织内引用、乐观锁或不可变 ID、同事务审计。当前组织隔离不等于站点级授权，也不包含真实人员身份历史证明。
- 工作台 Mock 经本机 API 导入带独立名称/source/provenance 的记录，复跑复用既有记录；设备协议验证则连接明确授权的本机 UDP/HTTPS 模拟器，模拟身份/读数不代表真实硬件。CONNECTED 不会因接口错误切换假数据。固定 NAT 有效区间和遥测时间不会自动延长。
- 已执行的前后端测试、Computer Use 逐页操作、Docker 健康及 Mock 幂等、Helm lint/render 以[验收报告](CLARITY-VERIFICATION.md)为准。本机 640 次/32 并发的有界查询冒烟不代表长期高并发、长历史或故障下的生产容量。
- SNMP/Redfish/固定档案 SSH 只读适配与内置 Worker 已有实现及协议模拟器验证；[六台真机验收](../devices/HARDWARE-VERIFICATION.md)已记录 Inspur Redfish 部分成功、Dell/三台 iMana SSH 成功、Cisco SSH 部分成功及六台周期采集，前端 71 项测试与生产构建通过；真实上线仍需逐型号/固件/认证组合的硬件验收、目标网络和凭据配置，外部 Edge 注册/心跳/缓冲能力及内置探测执行器的生产容量验证；实际 NAT/租约生命周期与时钟质量、历史站点/VRF 依据；签名/WORM/保留策略、数值告警与通知；目标 Kubernetes 镜像仓库、Secret、TLS、数据服务/持久存储、备份恢复及容量演练。模板可部署和本机 Mock 通过不能代替这些验收。
