# 控制台功能改进运行记录（2026-09-21）

## 功能与统计口径

- **七日带宽热力图**：整体为正方形，按两列四行排布七个日期组与图例；每天有 24 个正方形小时单元（八列三行），一个单元仍代表一小时。缺失、未来、夏令时缺失与部分覆盖分别显示，悬停、选中详情及表格保留数值和覆盖信息。
- **手动删除资产**：仅管理员可操作，并须在弹窗确认。服务端按组织隔离、记录操作者与审计事件，写入 `deleted_at` / `deleted_by` 墓碑，保留资产身份、接口、指标、事件及配置等历史。资产从当前目录、搜索、拓扑、汇总与调度候选中移除；设备连接、应用与 NAT 采集源停用，检查任务归档，不再发起新的采集。历史保留不表示旧版资产详情入口继续可用。
- **正在执行的任务**：删除与任务领取通过资产行锁协调；存在有效设备或应用采集租约、检查执行租约，或近期运行中的配置采集时，返回 `409 DEVICE_BUSY`，不级联删除任务或历史。可在任务结束后重试。已入队数据允许安全落库，但不得使已删除资产重新进入当前视图。
- **设备和接口筛选**：网络页可通过下拉框选择设备及其接口，筛选同步到 URL，支持刷新和浏览器前进、后退。切换站点清空设备和接口，切换设备清空接口；重置清除搜索、站点、设备、接口。接口必须属于当前组织及所选设备，接口精确筛选要求同时指定设备。
- **指标窗口统计**：均值使用整个所选时间窗口内有效原始样本的算术平均，不再平均图表降采样点。图表仅负责展示分桶趋势。带宽 Gauge 的流量是估算值：以相邻有效观测间的速率积分换算字节，超长间隔和缺失样本不外推；保留有效样本数、观测时长、覆盖率及估算标记。
- **应用流量统计**：使用采集区间的累计计数器差值字节，不使用计数器生命周期总量，也不混用 Gauge 估算值。有效区间按方向、接口和窗口汇总；边界按比例分摊并标记估算，历史缺少字节差值时使用带标记的速率估算。重叠区间排除，整数差值保持精度，汇总后统一舍入；平均速率按有效观测时长计算。总量包含所有匹配应用，图表仅展示排名靠前的应用；多接口合计可能存在重复观测，不等同于全网流量。
- **趋势粒度**：24 小时窗口按小时聚合，7 天窗口按天聚合。设备指标与应用流量沿用各自的数据来源和统计口径。
- **应用历史查询开销**：切换时间范围、筛选或手动刷新时重新查询；固定历史窗口不再每 20 秒重复扫描。ClickHouse 在窗口排序前解析并释放原始 JSON，使用有限前行窗口、去重质量标记与固定 32 MiB 阈值的排序磁盘溢写，不再叠加服务器内存比例门槛；聚合阶段由分组数和总内存硬上限约束，关闭因全查询内存触发的聚合落盘，避免反复生成小临时文件；单次查询仍限制 512 MiB 内存、1,200 万读取行、8 GiB 读取字节和 2 GiB 临时磁盘。超过 24 小时的查询允许 40 秒执行、45 秒 API 等待，其余保持 8 秒执行、10 秒等待。最终实际 API SQL 在生产数据上的七天只读预验收约 20 秒；超时和取消会清理对应查询，不返回截断结果冒充完整统计。
- **入口并发与超时**：仅 `GET /api/v1/applications/summary` 使用每实例 2 个名额、50 秒入口期限，避免原有 12 秒入口期限提前取消七天查询。其他普通接口保留 64 个名额和 12 秒期限；超额请求返回 429，未提交响应的超时返回 503，完成、错误与取消均释放名额。
- **拓扑布局**：使用 `vis-network`，采用其 Les Misérables 示例的 ForceAtlas2 参数预设并适配现有拓扑数据；保留缩放、拖动、物理布局开关、固定布局、节点与边的业务信息。尊重减少动态效果设置，更新数据时保留手动视角。
- **概览事件**：近期事件仅显示 `WARN` / `WARNING` / `CRITICAL` / `ERROR` / `FAULT` / `FATAL`，服务端先筛选再取最近记录，正常采集消息不挤占异常事件位置；完整历史查询不受影响。

## 上线顺序与回滚边界

1. 基于现网 Helm release 17 保存的完整有效 values 和 manifest 准备升级，保留 `runtime.existingSecret`、现有运行时 ConfigMap/Secret 引用、节点约束及其他环境参数。不得用仓库示例 values 整体覆盖现网配置，不得更换凭据加密密钥。私密文件仅放受限目录，不提交版本库。
2. 先备份现网 MySQL（实际位于 `noeriva-system`）。使用 `mysqldump --single-transaction` 并包含 routines、events、triggers 和二进制内容，备份压缩后校验可读性与校验和；同时私密保存运行时 Secret、加密密钥、Helm values 和 manifest。保留旧镜像。备份密码仅通过现有 Secret/进程环境传入，不能进入日志。
3. 将已验证的后端 JAR 和前端产物构建为唯一标签的 `linux/amd64` 镜像，预先导入两个节点的 k3s/containerd，核对镜像。现网采用 `IfNotPresent`，不能依赖重复标签触发更新。
4. 先更新 control 和 worker，保持旧 console，观察 Flyway 执行增量迁移 V13。control 为双副本滚动更新；worker 为单副本 `Recreate`，会有短暂采集空档。后端就绪并验证调度、历史与核心接口后，再更新 console；使用等待就绪和失败自动回滚选项，记录最终修订号。
5. 验收只读页面、接口筛选、统计口径与拓扑；删除验证使用专用测试资产，不能删除真实业务资产。确认采集恢复、历史可查、日志无新增异常后补充本记录。

V13 仅新增墓碑字段与索引，镜像回滚不应反向删除这些字段。**一旦使用了删除功能，旧版本会忽略墓碑，可能重新显示已删除资产并恢复部分调度行为；此时不能盲目回滚旧镜像。** 优先前向修复；如必须恢复旧版，应先评估墓碑数据与采集状态，再制定受控恢复方案。自动回滚只能处理部署失败，不能保证旧版理解新生命周期语义。
