# Implemented control, query and workbench API contract

Base path: `/api/v1`. UTF-8 JSON except the SSE response. The [OpenAPI description](../../schemas/api/openapi.json) is generated by `scripts/generate-openapi.py`, `scripts/workbench_openapi.py` and `scripts/device_access_openapi.py` and describes implemented endpoints only. Run `python3 scripts/validate-openapi.py` to compare every controller mapping and the typed workspace/workbench/device-access request/response DTOs against the generated contract.

Organization comes exclusively from the authenticated account. Console GET requests accept ADMIN/OPERATOR/VIEWER except `/devices/{id}/connections`, which requires ADMIN because it includes connection settings/usernames. All `/devices/{id}/connections/{slot}` writes and test/collect/state actions also require ADMIN. Ordinary console mutations accept ADMIN/OPERATOR. Repair-job creation and evidence/configuration imports require ADMIN. The audited read-only `POST /workbench/investigations` also accepts VIEWER. State ingestion requires COLLECTOR; `POST /workbench/check-results` and `/workbench/network-evidence` accept COLLECTOR or ADMIN. A collector-only account cannot use other console endpoints. Every mutation requires `Content-Type: application/json` and `X-Noeriva-Request: 1`.

Application errors have `{code,message,requestId}` and may return 400, 403, 404, 409, 429, 500 or 503. Authentication/authorization filters may return 401/403 with an empty body. Application 429 responses include `Retry-After: 1`. Responses include `X-Request-Id` and `Cache-Control: no-store`. Provider failures never become a complete empty/zero result. The workspace overview/search aggregates may preserve available components with HTTP 200, but history failure is explicitly marked `recentEventsStatus=UNAVAILABLE` and `HISTORY_UNAVAILABLE`. Direct history/metric endpoints still fail explicitly.

`mode` is DEMO for the explicit synthetic profile or CONNECTED for connected providers. Null represents absent information; there is no browser mock/fallback. Dates/timestamps use ISO-8601; response timestamps are UTC. Query `dataRevision`, device/alert `revision` and source `sequence` are JSON integers. Device-summary `dataRevision` is a decimal **string**; interface `speedBps` is an unsigned decimal **string**. Clients must preserve integer precision for large revisions.

## Session and overview

`GET /session` accepts Basic credentials and returns `{username,organizationId,roles,mode,timezone:null,accessToken,tokenType:"Bearer"}`. The frontend exchanges Basic credentials, then keeps the bearer token in memory. It is a random 256-bit opaque handle encoded as 43 base64url characters, valid for one hour after issuance, not a JWT. A Bearer-authenticated session read returns the same token without extending its lifetime. Current account permissions are checked on subsequent requests. Basic remains accepted by the API. There is no cookie authentication or refresh-token endpoint. The client chooses and labels an explicit timezone before requesting a heatmap.

Demo defaults are `admin / noeriva-local-demo` and `viewer / noeriva-local-demo`, overridable by the demo bootstrap password setting. Production requires configured credentials; it has no default password.

`GET /overview` returns `{devices,critical,warning,healthy,unknown,stale,activeAlerts,collectors,asOf,mode}`. Health counts are disjoint; stale overlaps those counts.

## Inventory and current state

`GET /devices?limit=50&cursor=<id>&q=&siteId=&type=&health=` returns `{items:Device[],nextCursor:string|null,asOf,source:"CONTROL",mode}`. Limit 1–100; stable device ID ascending order. Maximum lengths: cursor 64, q 120, siteId 64, type 32, health 16. Filters default to empty. Use returned cursors unchanged; reset pagination when filters change.

Device is `{id,name,type,siteId,siteName,vendor,model,managementAddress,health,availability,lastSeen,revision,capabilities:string[]}`. Types: HOST/BMC/SWITCH/ROUTER/FIREWALL. Health: HEALTHY/WARNING/CRITICAL/UNKNOWN. Availability: ONLINE/OFFLINE/UNKNOWN. Vendor, model and lastSeen may be null. `GET /devices/{id}` returns an authorized Device.

`POST /devices` accepts `{name,type,siteId,vendor?,model?,managementAddress}` and returns the committed Device with 201. Name is nonblank, at most 120 characters; site must exist. Optional vendor/model may be null, at most 120 characters. Address matches `[a-zA-Z0-9.:_-]{1,253}`; validation checks allowed characters, not strict IP syntax or DNS resolution. The device starts UNKNOWN. Connected creation commits inventory, audit and outbox together.

`GET /sites` returns `{items:[{id,name,timezone}],asOf}`; timezone may be null.

`GET /devices/{id}/summary` returns `{device:Device,sources:[{sourceId,kind,observedAt,sequence,epoch,health,metrics,freshness}],activeAlerts,asOf,sourceFreshness,coverage,resolution:0,dataRevision:string,provisional:false,qualityFlags:string[]}`. Each source has independent FRESH/STALE/MISSING freshness; observations older than 180 seconds are stale. Summary asOf is assembly time; source observedAt preserves observation time. Missing sources are absent. Metrics use only available finite values from the six-metric allowlist below; unsupported values are omitted, not null or zero-filled. Summary coverage is the fraction of listed sources that are fresh, not historical sample coverage. Parent host and BMC remain separate devices.

`GET /devices/{id}/interfaces` returns `{items:[{id,deviceId,name,macAddress,speedBps,adminStatus,operStatus}],asOf}`. MAC may be null. Speed is a 1–20 digit unsigned decimal string with value at most `18446744073709551615`.

`POST /devices/{id}/interfaces` accepts `{name,speedBps,macAddress?}` and returns the registered interface with 201. Name is nonblank, at most 120 characters; optional MAC metadata may be null, at most 40 characters. Admin/operational status starts UNKNOWN. This registers inventory metadata without operating a real device.

## Device management, credentials and read-only collection

The exact protocol contract is [DEVICE-INTEGRATION-API.md](../devices/DEVICE-INTEGRATION-API.md). The generated public schema contains every field from DeviceAccessModels and the public DeviceProtocol readings; persistence records, ciphertext and driver secret objects are deliberately excluded.

`GET /devices/{id}/management` returns `{device,inventoryRevision}`. `Device.revision` may be a telemetry checkpoint; only `inventoryRevision` is valid for inventory editing. `POST /devices/{id}/updates` accepts the six CreateDevice fields plus `{revision}` and returns the committed management object. ADMIN/OPERATOR; existing organization-local site required; changes and audit commit together. Metadata management-address changes do not redirect saved protocol connections. Stale versions return 409. Connected storage is required for writes; DEMO can read management but returns 503 for persistence.

`GET /device-support` returns `{items:[{id,vendor,family,protocols,implemented,verification,notes}],protocols,credentialStorageReady,collectorEnabled}`. Current profile verification is `SIMULATOR_TESTED_HARDWARE_PENDING`, distinct from the platform capability-maturity axes. `protocols` lists installed drivers. Storage readiness requires the encryption key and connected database. `collectorEnabled` reports the deployment hint `NOERIVA_DEVICE_POLLING_AVAILABLE`; it does not disable manual test/collect or credential saving.

`GET /devices/{id}/connections` requires ADMIN and returns `{items:ConnectionView[],asOf}`. This path previously represented a topology alias; it now represents credential-bearing connection settings. Each device has at most three slots: `snmp` maps to source `network`, `redfish` to source `bmc`, and `ssh` to source `ssh`. Read roles use `/collection` instead. ConnectionView includes username and flags indicating configured secrets, but never returns plaintext, ciphertext, credential storage references or lease tokens.

`POST /devices/{id}/connections/{slot}` requires ADMIN and returns ConnectionView with 200 for both create and update. The body is `{revision,host,port,enabled,intervalSeconds,timeoutMillis,maxInterfaces,username,snmpVersion,securityLevel,authProtocol,privacyProtocol,contextName,tlsMode,certificateSha256,secrets,sshProfile,sshHostKeySha256}`. Revision 0 creates (also the default if omitted); existing connections require the current positive revision. `enabled` defaults false. Host, port, interval, timeout and maximum interfaces are required. Host is 1–253 characters of hostname/IP syntax, without path, URI userinfo or IPv6 zone identifier. Port is 1–65535; interval 15–86400 seconds; timeout 250–10000 ms; maximum interfaces 1–256. Username is at most 120 characters; context at most 64.

SNMP requires version `2c` or `3`. v2c requires a read-only community. v3 requires a username and explicit `noAuthNoPriv`, `authNoPriv` or `authPriv`; authentication choices are MD5/SHA1/SHA256/SHA512, privacy choices AES128/DES. No algorithm downgrade is performed. Authentication/privacy passphrases newly supplied for v3 require at least eight characters. Redfish requires username/password and HTTPS trust mode SYSTEM or PINNED; PINNED requires a 64-hex-digit SHA-256 leaf fingerprint after colon removal. There is no skip-verification option. Inactive protocol fields normalize to empty strings: SNMP has empty TLS fields; Redfish has empty SNMP fields; v2c has no username/USM algorithms/context. SSH requires username/password, an explicit HUAWEI_IMANA/DELL_OS9/CISCO_IOS_XE profile and a canonical OpenSSH SHA256 host-key fingerprint (43 unpadded Base64 characters encoding exactly 32 bytes). The pin is checked before authentication; no arbitrary commands or automatic downgrade. Non-SSH sshProfile/sshHostKeySha256 canonicalize to null; SSH legacy SNMP/TLS strings canonicalize empty. Clients must compare normalized active fields before deciding whether credentials changed.

`secrets` has write-only nullable fields `community`, `authPassword`, `privacyPassword`, `password`, each at most 1024 characters. Null, absent or empty means retain only for the same normalized target/credential identity. Identity includes host, port, username, version/security algorithms, context, TLS mode/fingerprint and SSH profile/host-key fingerprint. Changing identity discards prior credential reuse and requires the new mode's secrets. All-mask placeholders and NUL are rejected. Secrets are AES-256-GCM encrypted with AAD bound to organization/device/slot; the master key is supplied separately. Unavailable key/storage is an explicit error and never falls back to plaintext. Saving a new config replaces the source epoch and resets latest test/published checkpoints; history providers are retained. The console saves disabled, but the API permits `enabled:true` without a prior successful test.

`POST /devices/{id}/connections/{slot}/test` and `/collect` require ADMIN and `{revision}`. These are synchronous bounded requests returning the updated ConnectionView, not 202 async jobs. A stale or busy leased connection returns 409; admitted work is capped at 16 concurrent reads per API process, a 30-second protocol budget, up to 24 seconds for publication and a 65-second admission budget. Test performs read-only protocol discovery and saves its result without publishing samples or changing scheduling. Collect additionally publishes into the existing interface/metric/state chain. Provider publication is not atomic; `PUBLICATION_FAILED` may leave samples in some stores.

Device/protocol/publication failures after lease acquisition are stored and normally return **200 with `status:ERROR`**, safe errorCode/errorMessage and timestamps. They must not be interpreted as successful readings merely because HTTP succeeded. Successful reads have SUCCESS or PARTIAL according to qualityFlags. Last successful reading/time are preserved on failed attempts.

`POST /devices/{id}/connections/{slot}/state` requires ADMIN and `{revision,enabled}` (`enabled` defaults false). It increments revision and enters QUEUED or DISABLED. The API does not require a successful prior test. A currently active read lease prevents state/config changes and returns 409; stopping does not cancel an already-issued protocol request. Scheduler intent is independent from test status and observed device health. Periodic execution is performed by the worker with database leases and version fencing, not inferred from an enabled flag in the UI.

`GET /devices/{id}/collection` returns `{items:CollectionView[],asOf}` for ADMIN/OPERATOR/VIEWER. CollectionView is `{slot,protocol,revision,enabled,status,lastAttemptAt,lastSuccessAt,nextPollAt,errorCode,errorMessage,lastReading}`. Status is NOT_TESTED/QUEUED/RUNNING/SUCCESS/PARTIAL/ERROR/DISABLED. The four time/error/reading groups may be null or empty as defined in OpenAPI; absence never means zero. DEMO returns an empty connection list for an existing synthetic device.

Reading is `{observedAt,identity,health,metrics,sensors,ports,capabilities,qualityFlags,facts}`. Identity includes vendor/family/profileId/model/serialNumber/firmware/sysObjectId/sysName/description; unavailable identity values may be null. Sensor values may be null. Ports preserve exact decimal-string capacities and counters; unavailable MAC/capacity/counters/discontinuity are null. A successful protocol identity response does not establish every vendor capability; only observed capabilities are listed, and generic matching remains explicit.

`GET /devices/{id}/live` is authenticated SSE for all read roles. Event `collection` contains the same safe collection response immediately and every three seconds. At most 64 streams per process, maximum lifetime ten minutes, and slow-client ticks may be dropped; disconnect/cancellation releases capacity. It has no replay cursor. Response uses `X-Accel-Buffering: no` and `Cache-Control: no-store`. Browser clients send Authorization via fetch headers, never in URL, and refetch after reconnect. HTTP errors apply before the stream begins; clients must also handle later disconnects.

## Stored-neighbor discovery and candidate review

The exact schemas are in [NETWORK-DISCOVERY-API.md](../devices/NETWORK-DISCOVERY-API.md) and generated OpenAPI. `POST /discovery/runs {sourceDeviceIds,cidr,siteId}` reviews saved SSH ARP/LLDP/CDP facts only, returning a synchronous RunResult with per-source USED/MISSING/STALE/INVALID, counts and quality flags. Source IDs are 1–8 distinct same-site assets; CIDR is explicit canonical IPv4 /24–/32. No scan, credential read or automatic collect. Source observations must be less than 15 minutes old and not in the future; known expired TTL entries are excluded. At most 256 observations/source and 2048/run.

`GET /discovery/candidates?siteId=&status=&cursor=&limit=50` returns a keyset Page with source DISCOVERY, mode CONNECTED and limit 1–100. Candidate fields include id/revision/address/siteId/name/mac/status/reasons/evidence/associatedDeviceId/firstSeenAt/lastSeenAt; evidence is at most 16 allowlisted records and never raw CLI. Last seen is source observation time, not online status. Shared MAC only raises duplicate suspicion; identity conflicts remain explicit.

`POST /discovery/candidates/{id}/register {revision,name,type}` registers an UNKNOWN asset or returns its existing association idempotently; CONFLICT cannot register. `POST .../{id}/link {revision,deviceId}` explicitly associates a same-organization/site asset. Neither operation moves credentials, changes target addresses or physically merges history. New associations require the current revision (409); same-target retries are idempotent, different existing associations conflict. Writes require ADMIN/OPERATOR; GET accepts all read roles. Admission is bounded to four operations per process, related review windows to 1024 rows and total operation/transaction time to ten seconds: 429 DISCOVERY_CAPACITY or 503 DISCOVERY_TIMEOUT, with cancellation rolling back writes.

## Metric queries and heatmaps

`GET /devices/{id}/metrics?metric=cpu_percent&from=<ISO>&to=<ISO>&points=120` returns `{deviceId,metric,unit,from,to,asOf,source,sourceFreshness,resolution,dataRevision,provisional,coverage,qualityFlags,points:[{timestamp,value:number|null}]}`.

Exact metric allowlist: `cpu_percent`, `memory_percent`, `temperature_celsius`, `power_watts`, `bandwidth_rx_bps`, `bandwidth_tx_bps`. Defaults: cpu_percent, to=now, from=to minus one hour, points=120. Positive range at most seven days; to allows five seconds of clock-skew tolerance. Points is a budget of 2–2000, not a promise of filled samples. Unassigned metric capability returns 409. Resolution is query step seconds; dataRevision is an integer; asOf may be null.

`GET /devices/{id}/interfaces/{interfaceId}/bandwidth/heatmap?timezone=Asia%2FShanghai&direction=rx&days=7&statistic=time_weighted_mean` returns `{deviceId,interfaceId,timezone,direction,statistic,unit,fromDate,toDate,asOf,source,sourceFreshness,dataRevision,coverage,resolution,provisional,qualityFlags,cells:[{date,hour,state,value,unit,aggregation,intervals:[{from,to,durationSeconds}],coverage,asOf,sourceFreshness,dataRevision,provisional,qualityFlags}]}`.

Timezone is required; use an IANA name (implementation validates Java ZoneId). Direction rx/tx defaults rx; only seven dates and time_weighted_mean are accepted. Current local date plus six preceding dates produce exactly 168 cells. Resolution=300 describes stored UTC rollups; cells represent local hours. DurationSeconds is an integer; a repeated hour has multiple UTC intervals. States: OBSERVED/OBSERVED_ZERO/MISSING/PARTIAL/FUTURE/DST_MISSING. Values and observation asOf may be null. Zero is an observed zero only; coverage ranges 0–1. Organization/device/interface ownership is checked before provider access; heatmap source is resolved from that authorized interface catalog `source_id` (manual registration primary; SNMP network), never a requester-selected source. Quality/provisional fields expose incomplete, recent or estimated data.

## Durable repair jobs

`POST /query-jobs` requires ADMIN and accepts `{deviceId,interfaceId,from,to,direction}`. Both IDs match `[A-Za-z0-9_.:@-]{1,64}`. Direction is rx/tx. The positive window is at most one day, both boundaries whole-second UTC five-minute boundaries, and to cannot be in the future. Organization/device/interface ownership is validated before resolving source from the authorized interface catalog `source_id` (manual registration primary; SNMP network). Source is not a request field. The resolved `sourceId` is persisted with the PENDING job and audit commit, and execution/lease retries use that stored job source rather than `NOERIVA_ROLLUP_SOURCE_ID`. At most 100 active jobs are admitted per organization; excess admission returns 429 JOB_QUEUE_CAPACITY. Success returns 202 with the job.

`GET /query-jobs/{id}` returns the job within the authenticated organization: `{id,type:"ROLLUP_REPAIR",organizationId,createdBy,deviceId,interfaceId,sourceId,direction,from,to,status,attempts,bucketCount:integer|null,errorCode:string|null,createdAt,updatedAt}`.

Status: PENDING/RUNNING/SUCCEEDED/FAILED. Attempts counts claims, 0–3. Successful jobs have bucketCount 1–288; failed jobs have errorCode. Those fields are otherwise null. Failure codes: LEASE_EXHAUSTED, DEADLINE_EXCEEDED, QUERY_CAPACITY, RECOMPUTATION_UNAVAILABLE, PROVIDER_UNAVAILABLE, INVALID_SOURCE_DATA, REPAIR_FAILED.

Both repair endpoints return 503 REPAIR_JOBS_UNAVAILABLE in demo. Connected processing requires `NOERIVA_ROLLUP_ENABLED=true`; disabled processing can leave accepted jobs PENDING. Each claim has a 30-second deadline and two-minute lease. Expired leases can be reclaimed up to three total claims; lease tokens prevent stale completion. Missing/unretained raw inputs fail explicitly. No export is produced.

## Topology, events and alerts

`GET /topology?deviceId=&limit=200` returns `{nodes:[{id,name,type,health}],edges:[{id,source,target,sourceInterface,targetInterface,kind,provenance,observedAt}],asOf,qualityFlags}`. Bound: 200 nodes/400 edges; interface names may be null. The former `/devices/{id}/connections` topology alias now serves ADMIN connection settings; use the topology query parameter for device scoping. Synthetic relationships carry SIMULATED provenance. Temporal topology is not implemented. Saved SSH neighbor evidence is reviewed through the separate discovery API; it does not automatically create topology edges or scan a network.

`GET /events?deviceId=&limit=50&cursor=&from=<ISO>&to=<ISO>` or `GET /devices/{id}/activity` returns `{items:[{id,deviceId,kind,severity,message,observedAt,ingestedAt,source,qualityFlags}],nextCursor,asOf,source,mode}`. Message/nextCursor may be null. Limit 1–100, cursor at most 512 characters, positive window at most 31 days. Defaults: to=now, from=to minus seven days. A path device ID overrides the query parameter. Event cursors are opaque; messages render as text.

`GET /alerts?deviceId=&state=OPEN&limit=50` returns `{items:[{id,deviceId,deviceName,severity,state,title,openedAt,acknowledgedAt,acknowledgedBy,revision}],asOf}`. Default state filter is empty (all states); values OPEN/ACKNOWLEDGED/RESOLVED. Limit 1–100. Acknowledgement fields may be null. `POST /alerts/{id}/acknowledge` with `{revision:1}` returns the committed Alert. Revision is at least 1. Conflicts return 409, including stale repeated acknowledgements; refresh before retrying. Acknowledge does not resolve the problem.

## Collectors and capabilities

`GET /collectors` returns `{items:[{id,name,siteId,status,lastHeartbeat,lastSuccessfulCollection,queueBytes,queueLimitBytes,oldestQueuedAt,version,capabilities,source}],asOf}`. Collection timestamps may be null. There is currently no collector registration, heartbeat or queue-state write endpoint. `/ingest/batches` projects device/source state, not collector heartbeats. An empty CONNECTED collector directory is expected before that integration exists; a synthetic DEMO collector does not establish a verified real adapter.

`GET /capabilities` returns `{items:[{id,name,roadmapTier,maturity,coverage,verification,phase,notes}],mode}` for eleven domain summaries: inventory, workspace, metrics, alerts, incidents, configuration, checks, nat, evidence, network and governance. Roadmap tier, maturity, partial coverage and verification are independent fields. Verification may be FIXTURE_TESTED, INTEGRATION_TESTED or NOT_TESTED. Imported records and collector-reported results establish partial workflows; they do not prove a probe executor, signature service or WORM storage. Read-only device protocol driver evidence is reported separately by `/device-support`, with hardware acceptance still pending. The [full machine capability matrix](../capabilities/capability-matrix.json) retains the complete roadmap. Synthetic automated tests do not establish DEVICE_VERIFIED support.

## Realtime

`GET /stream/device-status` is authenticated SSE. Event snapshot-required is emitted initially and every 15 seconds with JSON data `{revision,asOf}`. Revision is a connection-local integer counter, not a durable data revision or resume cursor. Hints prompt snapshot refetch; fetch a complete snapshot on reconnect. The separate device-specific `/devices/{id}/live` stream carries safe collection snapshots; this general stream does not carry per-metric samples. At most 200 streams per process; slow-client hints may be dropped, and cancellation/disconnect releases capacity.

## Collection ingestion

`POST /ingest/batches` requires COLLECTOR and accepts `{batchId,events:[{id,deviceId,sourceId,kind,epoch,sequence,observedAt,health,metrics,message?}]}`. Carries 1–500 low-volume state events, not raw metric samples. Batch/event IDs match `[a-zA-Z0-9_-]{1,128}`. Device ID/epoch are nonblank and at most 64 characters. Exact source allowlist: primary, host, bmc, network, system, ssh. Kind: DeviceSummaryObserved/SourceHealthChanged. Health uses the inventory health enum. Sequence is an integer from 0 through `9223372036854775806`.

Metrics is required, may be empty, and only permits finite non-null numeric values for the six named metrics above. Optional message may be null, at most 1000 characters. ObservedAt is at least `2000-01-01T00:00:00Z` and no more than 120 seconds ahead of server time. Same-epoch updates require greater sequence and nondecreasing observation time; changed epoch requires strictly newer time.

Production returns 202 `{batchId,status:"DURABLY_QUEUED",accepted,receivedAt}` after all sends receive Kafka acks=all. Batch resource scope is validated before publication, but publication is not atomic: a failed request can leave a durable subset. Retry with stable event IDs, epoch and sequence. Demo returns SIMULATED without a durability claim. Source observation times remain distinct from ingestion time.

## Clarity workspace and workbench extensions

The [workspace contract](WORKSPACE-API.md) defines `/workspace/monitoring`, `/workspace/interfaces`, `/workspace/overview` and `/workspace/search`. Monitoring pages return current sources and their metric maps through bounded joins; unknown inventory never invents sensor rows. Interface freshness refers explicitly to the device checkpoint. Overview counts are computed over the full authorized site scope, and its optional traffic source represents one named device. Event search is limited to the latest 100 retained events within seven days and exposes that coverage.

The [workbench contract](WORKBENCH-API.md) defines incident lifecycle/notes; immutable text evidence and an unsigned checksum manifest; redacted configuration snapshots and bounded line diffs; collector-reported check definitions/results; typed NAT/address-lease evidence and temporal candidate investigation; and organization-scoped audit pages. Lists use bounded keyset pagination. Mutations use organization scope, optimistic revisions or stable idempotency IDs, and transactional audit records.

These workbench endpoints execute the documented workflows with imported data. The separate device-access endpoints add read-only SNMP/Redfish/fixed-profile SSH protocol execution and periodic collection. Automatic synthetic-check execution, remote configuration push/restore, signed evidence, WORM storage, and personnel attribution remain outside the implemented contract. An unsigned checksum manifest is available; it is not a signed forensic export.
