## Cisco 授权修复

系统四个基础 OID 的批量、单项读取，从部署服务器和本机均返回 authorizationError。HTTPS 只读检查确认：监测用户仍存在且为 SHA/AES128，但引用的权限组已缺失；原有来源 ACL 仍允许部署节点。恢复原组后，同一凭据从部署节点读取系统对象成功。仅增补 LLDP/CDP view 范围，未开放写 view。保存命令返回 `[OK]`。

使用现有证书的 SHA-256 固定校验，在发送认证头之前验证证书一致性；没有将认证信息放入命令行或验收文档。Cisco 的 HTTP/HTTPS 管理接口依据：[IOS XE 17 HTTP 服务指南](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/https/configuration/xe-17/https-xe-17-book/HTTP_1-1_Web_Server_and_Client.html)。

## 采集与展示语义

- 配置读取只选择启用连接，优先 SNMP，其次 Redfish；选定来源失败时呈现失败，不隐式使用 SSH。`SNMP_DEVICE_BASELINE` 是身份与接口基线，不声称是完整 running-config。
- 禁用连接不能手动发布采集，避免重新占用指标；显式连接测试仍独立保留。
- SNMP LLDP/CDP 使用受限表读取，保留源 OID、真实本地接口与远端身份。拓扑及发现按每设备单一启用来源读取，旧 SSH 邻居不得覆盖当前 SNMP 故障。
- Cisco 现场 LLDP 中一个邻居是 Dell，另一个是 Ruijie。不得把两个邻居都显示为 Dell，也不得把 Ruijie 广告的环回管理地址当作可探测目标。
- iMana 温度、风扇和电源读数按实测类型解析；CPU DTS 为相对温差，不进入整机绝对温度汇总。整机功耗采用独立系统功率 OID，不叠加 PSU 读数造成重复统计。未核验的 IPMI 状态位保留原值，不推断为健康正常。
